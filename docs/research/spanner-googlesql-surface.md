# Research: Spanner GoogleSQL DDL, DML and type system

Resolves issue #3. Research date: 2026-07-29. All facts come from the official Spanner documentation. Each section links its source pages.

## 1. Type system and candidate Drizzle mapping

Source: [GoogleSQL data types](https://docs.cloud.google.com/spanner/docs/reference/standard-sql/data-types).

| Spanner type | Key facts | TypeScript type | Candidate Drizzle column |
|---|---|---|---|
| `INT64` | 64-bit signed integer. Range is -2^63 to 2^63-1. This range exceeds `Number.MAX_SAFE_INTEGER`. | `bigint` (default) or `number` (opt-in) | `int64('col', { mode: 'bigint' \| 'number' })` |
| `FLOAT64` | Double precision. 8 bytes. Supports `NaN` and infinity. | `number` | `float64('col')` |
| `FLOAT32` | Single precision. 4 bytes. Not allowed in a primary key. | `number` | `float32('col')` |
| `NUMERIC` | Fixed decimal. Precision 38, scale 9. | `string` (lossless) or `number` (lossy opt-in) | `numeric('col', { mode: 'string' \| 'number' })` |
| `STRING(n \| MAX)` | UTF-8 text. A length is mandatory in DDL. One cell holds up to 2,621,440 characters ([quotas](https://docs.cloud.google.com/spanner/quotas)). | `string` | `string('col', { length: n \| 'MAX' })` |
| `BYTES(n \| MAX)` | Binary data. A length is mandatory in DDL. | `Uint8Array` / `Buffer` | `bytes('col', { length: n \| 'MAX' })` |
| `BOOL` | `TRUE` or `FALSE`. | `boolean` | `bool('col')` |
| `DATE` | Calendar date. Range is 0001-01-01 to 9999-12-31. No time zone. | `string` (`YYYY-MM-DD`) or `Date` | `date('col', { mode: 'string' \| 'date' })` |
| `TIMESTAMP` | Absolute point in time. Nanosecond storage, microsecond API granularity. No time zone attached. | `Date` (default) or `string` | `timestamp('col', { mode: 'date' \| 'string' })` |
| `JSON` | Document type. Spanner canonicalizes the value. Nesting depth is at most 80 levels. Not orderable. Not groupable. Not allowed in a primary key. | `unknown` / generic `T` | `json('col').$type<T>()` |
| `ARRAY<T>` | Ordered list. Arrays cannot contain arrays directly. Not allowed in a primary key. | `T[]` | `.array()` modifier on the element builder |
| `TOKENLIST` | Token list for full-text search. Created by tokenizer functions in hidden generated columns. Only search indexes consume it ([full-text search](https://docs.cloud.google.com/spanner/docs/full-text-search)). | not readable as a value | `tokenlist('col').generatedAlwaysAs(sql\`TOKENIZE_FULLTEXT(...)\`).hidden()` |
| `PROTO` | Protocol buffer message. Needs a `PROTO BUNDLE`. Not orderable ([protocol buffers](https://docs.cloud.google.com/spanner/docs/reference/standard-sql/protocol-buffers)). | `Uint8Array` or a decoded message type | `proto('col', 'package.Message')` — defer to a later phase |
| `ENUM` | Protocol buffer enum. Maps names to integers. Needs a `PROTO BUNDLE`. | `number` or a literal union | `protoEnum('col', 'package.Enum')` — defer to a later phase |

Extra type facts:

- `STRUCT` cannot be a column type. It only appears in query results.
- A primary key cannot use `FLOAT32`, `ARRAY`, `JSON`, or `STRUCT`.
- `PROTO` and `JSON` are not comparable. `ORDER BY`, `GROUP BY`, and `DISTINCT` reject `ARRAY`, `JSON`, `PROTO`, and `STRUCT`.
- Spanner also has a `UUID` type (128-bit) and an `INTERVAL` type. The adapter can add these later.
- A cell holds at most 10 MiB. A key (primary or index) is at most 8 KiB per row ([quotas](https://docs.cloud.google.com/spanner/quotas)).

## 2. DDL rules

Source: [GoogleSQL DDL reference](https://docs.cloud.google.com/spanner/docs/reference/standard-sql/data-definition-language).

### Primary keys

- Every table must declare a primary key.
- The clause sits after the column list: `CREATE TABLE t (...) PRIMARY KEY (col [ASC|DESC], ...)`.
- Classic `AUTO_INCREMENT` / `SERIAL` does not exist.

### Key generation alternatives

Source: [Primary key default values](https://docs.cloud.google.com/spanner/docs/primary-key-default-value).

1. **Identity columns**: `SingerId INT64 GENERATED BY DEFAULT AS IDENTITY (BIT_REVERSED_POSITIVE)`. This is the recommended integer strategy.
2. **Bit-reversed sequences**: `CREATE SEQUENCE s OPTIONS (sequence_kind="bit_reversed_positive")`, then `DEFAULT (GET_NEXT_SEQUENCE_VALUE(SEQUENCE s))`. A database option `default_sequence_kind = 'bit_reversed_positive'` can set the default kind.
3. **UUID defaults**: `Id STRING(36) DEFAULT (GENERATE_UUID())`, or the native `UUID` type with `DEFAULT (NEW_UUID())`.

Monotonic keys create write hotspots. Bit reversal and UUIDs spread writes across the key space.

### INTERLEAVE IN PARENT

- Syntax: `CREATE TABLE child (...) PRIMARY KEY (...), INTERLEAVE IN PARENT parent ON DELETE { CASCADE | NO ACTION }`.
- The child key must start with the full parent primary key.
- `ON DELETE CASCADE` deletes child rows with the parent. `ON DELETE NO ACTION` blocks the parent delete while child rows exist. `NO ACTION` is the default.
- Google recommends interleaving **or** foreign keys for one parent-child relation, not both ([foreign keys overview](https://docs.cloud.google.com/spanner/docs/foreign-keys/overview)).

### allow_commit_timestamp

Source: [Commit timestamps](https://docs.cloud.google.com/spanner/docs/commit-timestamp).

- Only `TIMESTAMP` columns accept `OPTIONS (allow_commit_timestamp = true)`.
- DML writes the value with `PENDING_COMMIT_TIMESTAMP()`. The mutation API uses the `spanner.commit_timestamp()` placeholder string.
- After a statement calls `PENDING_COMMIT_TIMESTAMP()`, the transaction cannot read that table or its indexes again. Put such writes last.
- The value must not be in the future. A future value causes a `FailedPrecondition` error.
- Foreign keys cannot reference commit timestamp columns. Generated columns cannot use or reference them ([generated columns](https://docs.cloud.google.com/spanner/docs/generated-column/how-to)).
- Parent and child keys must use consistent `allow_commit_timestamp` settings.

### Secondary indexes

Source: [Secondary indexes](https://docs.cloud.google.com/spanner/docs/secondary-indexes).

- Syntax: `CREATE [UNIQUE] [NULL_FILTERED] INDEX name ON table (col [ASC|DESC], ...) [STORING (col, ...)] [, INTERLEAVE IN parent]`.
- `NULL_FILTERED` excludes rows with a NULL key part. This shrinks sparse indexes.
- `STORING` copies extra columns into the index. Queries can then avoid a base-table join.
- An interleaved index requires the parent primary key as a prefix of the index key.
- Queries force an index with the hint `@{FORCE_INDEX=name}`.
- A table holds at most 128 indexes ([quotas](https://docs.cloud.google.com/spanner/quotas)).

### Foreign keys

Source: [Foreign keys overview](https://docs.cloud.google.com/spanner/docs/foreign-keys/overview).

- Syntax: `CONSTRAINT fk FOREIGN KEY (cols) REFERENCES t (cols) [ENFORCED | NOT ENFORCED] [ON DELETE CASCADE]`.
- Actions are `ON DELETE NO ACTION` (default) and `ON DELETE CASCADE`. `ON UPDATE` actions do not exist.
- `NOT ENFORCED` (informational) foreign keys skip validation. They help the optimizer. They are GoogleSQL-only.
- Spanner creates hidden backing indexes. Referenced columns must be unique.
- Foreign keys cannot use `ARRAY`, `JSON`, or commit timestamp columns.
- DML validates per statement. The mutation API validates at commit.

### Check constraints and generated columns

Sources: [DDL reference](https://docs.cloud.google.com/spanner/docs/reference/standard-sql/data-definition-language), [generated columns](https://docs.cloud.google.com/spanner/docs/generated-column/how-to).

- Check constraints: `CONSTRAINT name CHECK (expression)`.
- Generated columns: `col type AS (expression) STORED`. Omit `STORED` for a virtual column.
- The expression must be deterministic. Subqueries are not allowed. The expression cannot reference other tables or other generated columns.
- A generated column can be a primary key part under limits: it may reference at most one non-key column.
- Clients cannot write to generated columns.

### DEFAULT expressions

Sources: [DDL reference](https://docs.cloud.google.com/spanner/docs/reference/standard-sql/data-definition-language), [primary key defaults](https://docs.cloud.google.com/spanner/docs/primary-key-default-value).

- Syntax: `col type DEFAULT (expression)`.
- The expression can be nondeterministic (for example `GENERATE_UUID()`, `CURRENT_TIMESTAMP()`).
- The expression cannot reference other columns. It cannot contain subqueries, query parameters, aggregates, or analytic functions.
- Primary key columns accept defaults. This enables client-free key generation.

## 3. DML behavior

Source: [GoogleSQL DML reference](https://docs.cloud.google.com/spanner/docs/reference/standard-sql/dml-syntax).

- `INSERT [OR IGNORE | OR UPDATE] INTO t (...) VALUES (...) | select_query`.
- `INSERT ... ON CONFLICT (pk_or_unique_cols) DO NOTHING | DO UPDATE SET col = EXCLUDED.col [WHERE ...]` also exists. `OR IGNORE/OR UPDATE` and `ON CONFLICT` cannot mix in one statement. The conflict target cannot be a null-filtered unique index.
- `UPDATE` and `DELETE` require a `WHERE` clause. Use `WHERE true` to affect all rows.
- **THEN RETURN**: `... THEN RETURN [WITH ACTION [AS alias]] { * | expr [AS alias] } [EXCEPT (...)] [REPLACE (...)]`. It works on INSERT, UPDATE, and DELETE. It returns generated keys, default values, and generated columns. `WITH ACTION` adds an action column. This is the Drizzle `.returning()` target.
- **Parameters**: GoogleSQL uses named parameters with the `@name` syntax. The client sends values in the `params` map with optional `paramTypes`. Positional `?` does not exist in GoogleSQL.
- **Limits** ([quotas](https://docs.cloud.google.com/spanner/quotas)):
  - At most 80,000 mutations per commit, indexes included. Each changed column counts.
  - Commit size at most 100 MiB.
  - At most 40,000 DML statements per transaction ([DML reference](https://docs.cloud.google.com/spanner/docs/reference/standard-sql/dml-syntax)).
  - Partitioned DML does not support `INSERT`. Batch DML (`executeBatchDml`) allows at most one `INSERT OR IGNORE`/`OR UPDATE` statement.

## 4. Emulator gaps

Sources: [Emulator docs](https://docs.cloud.google.com/spanner/docs/emulator), [emulator README](https://github.com/GoogleCloudPlatform/cloud-spanner-emulator/blob/master/README.md).

The emulator does not support:

- TLS/HTTPS, authentication, IAM, permissions, or roles.
- Backup APIs and audit logging or monitoring tools.
- Query plans: `PLAN` and `PROFILE` modes return an empty plan.
- `ANALYZE`: accepted but ignored.
- Persistence: all data lives in memory and vanishes on shutdown.
- Concurrency: one read-write transaction or schema change at a time. Others abort. Production behaves differently.
- Partitioned DML validation: the emulator accepts non-partitionable statements that production rejects.
- `SPANNER_SYS` introspection tables (mostly unsupported).
- Some full-text search options (`language_tag`, `enhance_query`, `content_type`, `token_category`) have limited handling.
- Foreign key backing index names differ from production.
- Error messages can differ from production.

Consequence for the adapter: integration tests on the emulator must run schema changes and transactions serially. Tests must not assert on exact error messages.

## 5. Adapter implications (summary)

- The dialect must render `PRIMARY KEY` outside the column list and support `INTERLEAVE IN PARENT`.
- The dialect must not emit `AUTO_INCREMENT`. It must offer identity columns, sequences, and UUID defaults.
- `STRING` and `BYTES` require an explicit length; default to `MAX` when the user gives none.
- `.returning()` maps to `THEN RETURN`.
- The driver must bind named `@p1`-style parameters, not `?`.
- Upserts map to `INSERT OR UPDATE` or `INSERT ... ON CONFLICT`.
- `TOKENLIST`, `PROTO`, and `ENUM` need proto bundles or search indexes; treat them as phase-2 features.
